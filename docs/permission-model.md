# 权限与安全模型

## 1. 两层身份

服务端统一使用企业 App ID/App Secret 获取领星 OpenAPI token。这个 token 能访问企业开放接口授权范围内的数据，不能代表某个普通 ERP 用户。

每个 MCP `X-Mcp-Key` 绑定一个 ERP `uid`。服务只保存 Key 的 SHA-256 派生哈希，不保存明文；Key 明文仅在创建时显示一次。

## 2. 权限同步

服务调用：

- `/erp/sc/data/account/lists`：读取 `uid`、用户名、角色名称、店铺权限、主账号状态；
- `/erp/sc/data/seller/lists`：把店铺名称映射为 `sid` 和 `seller_id`。

不会保存接口返回的手机号、邮箱、登录 IP 等个人信息。

同步使用严格匹配：

- 未找到用户：拒绝；
- 店铺名称不存在：拒绝；
- 同名店铺对应多个 `sid`：拒绝；
- 普通用户店铺权限为空：允许店铺集合为空；
- 主账号店铺字段为空：同步企业全部店铺。

默认每 300 秒重新同步。过期后无法同步时，新的 MCP 请求返回 503，不继续使用过期权限。

## 3. 功能角色映射

公开 OpenAPI 只返回角色名称，不返回角色所包含的菜单和功能权限。因此管理员必须维护角色映射：

```json
{
  "roles": {
    "销售专员": [
      { "module": "basic", "access": "read" },
      { "module": "sales", "access": "read" }
    ]
  }
}
```

`write` 包含同模块的读权限；只有 `read` 不能调用写接口。可以用 `endpoint_id` 把授权限制到单个接口。

## 4. 店铺范围

目录生成器从请求文档识别 `sid`、`sids`、`sid_list`、`seller_id` 等店铺选择器。

- 调用方传值时，所有值必须属于当前用户；
- 数组参数缺失时，服务端注入当前用户全部允许店铺；
- 标量参数缺失且用户只有一个店铺时自动注入；
- 标量参数缺失且用户有多个店铺时拒绝，防止上游默认查询全部店铺；
- 店铺列表和账号列表接口会对响应再次过滤。

## 5. 无法收窄的接口

大量企业级财务、仓库、产品接口没有可验证的店铺参数，被标记为 `unscoped`。普通模块授权不足以调用这类接口，必须额外配置：

```json
{
  "module": "finance",
  "access": "read",
  "endpoint_id": "POST /某个精确路径",
  "allow_unscoped": true
}
```

这类授权可能查看跨店铺数据，应仅授予主账号或经过业务确认的管理角色。

## 6. 写操作

标题或路径包含创建、修改、删除、入库、出库、发货、同步等副作用语义的接口标记为 `write`。无法可靠识别的接口也默认标记为 `write`。

写操作必须：

1. 使用 `call_write_endpoint`；
2. 角色拥有模块或精确端点的 `write` 授权；
3. 通过店铺范围校验；
4. 记录审计日志。

## 7. 会话边界

Streamable HTTP 会话在初始化时绑定 Key ID。之后每个 POST、GET SSE 和 DELETE 请求都会重新验证 Key：

- Key 被吊销后，会话立即不能继续调用；
- 使用另一个有效 Key 访问已有会话返回 403；
- 会话默认 30 分钟无活动后清理。

## 8. 审计

审计记录包含时间、Key ID、ERP uid、工具动作、接口 ID、允许/拒绝、请求字段名和安全错误码，不记录：

- App Secret；
- access token；
- 签名；
- API Key 明文；
- 完整业务请求和业务响应。
